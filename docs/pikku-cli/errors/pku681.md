# PKU681: Scenario Step Prose Names Its Actor

## Error Message

```
[PKU681] Scenario 'checkoutFlow' names its actor in the step prose: 'Shopper buys an apple' runs as 'shopper'. The reporter already renders the actor as the subject, so this reads "Given shopper Shopper buys an apple". Drop the name and let { actor: actors.shopper } supply it — the step reads as a bare third-person predicate.
```

## What Went Wrong

A step declares who it runs as via `{ actor: actors.shopper }`, and its prose *also* opens with that persona's name — `'Shopper buys an apple'`, or `` `'shopper' buys an apple` ``.

The reporter composes each line as **phase + actor + prose**, so it already supplies the subject. Naming the actor again at the front of the prose doubles it up: the generated report reads "Given shopper Shopper buys an apple", and in a report where the actor is its own column or line prefix, the name is printed twice side by side. There's a correctness cost too — the hardcoded name silently desyncs the moment the call site switches actor, so a step you re-run as `actors.admin` still claims to be the shopper.

Only the **subject position** is refused. Naming someone mid-sentence ("sends shopper a receipt") is ordinary prose and passes, and a persona keyed after a role noun can still say "creates the admin client".

Pikku checks every string that could render for the step, in the runtime's own precedence: the call-site `description`, the step's `template`, the step definition's `description`, and the step name itself. So a clean step name won't save you if the `description` you passed opens with the actor.

## How to Fix

Delete the name from the front of the prose and let the `actor:` option supply it. What's left should read as a bare third-person predicate — something that makes sense with "Given \<someone\>" glued in front of it.

```typescript title="checkout.scenario.ts"
// ❌ Wrong — causes PKU681
export const checkoutFlow = pikkuScenario<void, { setUp: true }>({
  title: 'A buyer completes checkout',
  tags: ['scenario'],
  func: async (_services, _data, { scenario, actors }) => {
    await scenario.given(
      'Shopper has an item in the cart',
      'addToCart',
      { sku: 'A1' },
      { actor: actors.shopper }
    )
    await scenario.then(
      `'shopper' sees the order confirmed`,
      'seesOrderStatus',
      { status: 'confirmed' },
      { actor: actors.shopper }
    )
  },
})
```

```typescript title="checkout.scenario.ts"
// ✅ Correct — the actor is declared once, in the option
export const checkoutFlow = pikkuScenario<void, { setUp: true }>({
  title: 'A buyer completes checkout',
  tags: ['scenario'],
  func: async (_services, _data, { scenario, actors }) => {
    await scenario.given(
      'has an item in the cart',
      'addToCart',
      { sku: 'A1' },
      { actor: actors.shopper }
    )
    await scenario.then(
      'sees the order confirmed',
      'seesOrderStatus',
      { status: 'confirmed' },
      { actor: actors.shopper }
    )
  },
})
```

Prose rewrites, before and after:

| ❌ Prose that trips PKU681 | ✅ Prose that renders cleanly |
| --- | --- |
| `'Shopper buys an apple'` | `'buys an apple'` |
| `` `'shopper' buys an apple` `` | `'buys an apple'` |
| `"shopper's cart is empty"` | `'has an empty cart'` |
| `'Susan opens the catalogue'` | `'opens the catalogue'` |
| `'admin approves the order'` | `'approves the order'` |

### If the offending string is the call-site description

The `description` overrides the step name, so it's what actually renders — and it's checked for exactly that reason:

```typescript title="checkout.scenario.ts"
// ❌ Wrong — the step name is fine, but the description is what renders
await scenario.given(
  'buys an apple',
  'buysAnApple',
  { qty: 1 },
  { actor: actors.shopper, description: 'shopper buys an apple' }
)

// ✅ Correct
await scenario.given(
  'buys an apple',
  'buysAnApple',
  { qty: 1 },
  { actor: actors.shopper, description: 'buys a single apple' }
)
```

### If the offending string is on the step definition

A step's own `description` or `template` is authored before any call site exists, so if it names a persona it is wrong at *every* call site that runs as that persona — not just the one the error pointed at. Fix it once at the definition:

```typescript title="steps/buys-an-apple.step.ts"
// ❌ Wrong — the template hardcodes the persona
export const buysAnApple = pikkuScenarioStep({
  name: 'buysAnApple',
  template: 'shopper buys {qty} apples',
  func: async (services, data) => { /* … */ },
})

// ✅ Correct — the predicate only; the actor comes from the call site
export const buysAnApple = pikkuScenarioStep({
  name: 'buysAnApple',
  template: 'buys {qty} apples',
  func: async (services, data) => { /* … */ },
})
```

### If you genuinely need two people in one line

You don't have to strip the name from the middle of a sentence — only from the front. A step run as `actors.admin` that mentions the shopper is fine:

```typescript
// ✅ Correct — the subject is the actor; 'shopper' is the object
await scenario.then(
  'sends shopper a receipt',
  'sendsReceipt',
  {},
  { actor: actors.admin }
)
```

## Scenario Best Practices

- Write step prose as a bare predicate: start with the verb ("opens", "sees", "approves"), never with a name.
- Read each line back as "Given \<actor\> \<prose\>" before committing it — if that sentence has the name twice, it's PKU681.
- Keep the persona in exactly one place per step: the `{ actor: … }` option. That's what makes a step reusable across actors.
- Put reusable wording on the step's `template` so every call site inherits prose that's already actor-neutral.
- Quotes and capitalisation are decoration, not an escape hatch — `` `'shopper' …` ``, `"Shopper …"` and `shopper's …` are all caught.

## Common Mistakes

```typescript title="wrong.ts"
// ❌ Wrong — causes PKU681: the subject is declared twice
await scenario.when(
  'Susan searches for coffee',
  'searchesAddons',
  { query: 'coffee' },
  { actor: actors.susan }
)
```

```typescript title="correct.ts"
// ✅ Correct — reads as "When susan searches for coffee"
await scenario.when(
  'searches for coffee',
  'searchesAddons',
  { query: 'coffee' },
  { actor: actors.susan }
)
```

```typescript title="wrong.ts"
// ❌ Wrong — causes PKU681: possessive opening still names the subject
await scenario.given(
  `shopper's cart is empty`,
  'emptyCart',
  {},
  { actor: actors.shopper }
)
```

```typescript title="correct.ts"
// ✅ Correct
await scenario.given('has an empty cart', 'emptyCart', {}, { actor: actors.shopper })
```
